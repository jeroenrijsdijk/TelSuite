telonline.org — telrapport.html input specification
Telrapport.html accepts five ZIP archive types and one loose CSV. The format is detected from the app_type field in _sessie.csv for ZIPs, or from the file structure for loose CSV (stand-still). All CSV files use semicolon delimiters and UTF-8 encoding. Inside a ZIP, file names must start with the session ID and end with the suffix shown below.

_capaciteit.csv
sessie_id;osm_way_id;naam;zijde;soort;capaciteit;eerste_waarneming;laatste_waarneming 20260429_094659_mat;142108527;Damstraat;L+R;regulier;50;2026-04-29T07:46:42;2026-04-29T07:52:10 20260429_094659_mat;142108527;Damstraat;L+R;gehandicapt;2;2026-04-29T07:47:05;2026-04-29T07:47:05 20260429_094659_mat;;(niet gesnapped);L+R;regulier;3;2026-04-29T07:49:31;2026-04-29T07:50:02
One row per (naam × soort), aggregated by street name — not by way. A street split into several OSM ways still yields one row per soort.
osm_way_id is therefore a representative, not a key: the first way ID seen under that name. Do not join on it expecting one-to-one; join on naam, or expand through _netwerk.csv.
capaciteit is the number of taps in that group — one tap is one parking space.
soort: regulier / gehandicapt / laadpaal / gereserveerd. A soort with a zero count gets no row at all.
zijde is always L+R: a capacity count sums both kerbsides of a street. Per-side detail is in _telregels.csv.
Taps that could not be snapped to a way are gathered in their own rows with naam=(niet gesnapped) and an empty osm_way_id, one per soort. The capaciteit column therefore always sums to n_waarnemingen in _sessie.csv.
eerste_waarneming / laatste_waarneming bracket the taps inside that one (naam × soort) group, not the whole street. ISO local time, no zone.
The _cap marker lives in the ZIP name only; sessie_id itself is YYYYMMDD_HHMMSS_xyz, so the member file is <sessie_id>_capaciteit.csv.

One row per way, de-duplicated on osm_way_id. Ways with fewer than two geometry points are dropped.
Holds the whole network gathered during the session, not just the ways that were counted — so telrapport can draw areas and streets straight from the file and skip the Overpass call. Expect rows without a matching _capaciteit.csv entry; that is not an error.
Omitted from the ZIP entirely when no geometry was gathered, rather than written as a header-only file. Readers should treat it as optional.
Same three columns as the auto / bike variant, so one reader fits all app types; only capacity sessions can contain POLYGON rows.

segment_index (0-based) indicates which ~40m segment of the way was hit.
conf / conf_level: snap confidence appended after the stable columns. conf is a 0–1 score (weakest link of: margin to the runner-up way, snap distance, GPS accuracy); conf_level is green / amber / red. They are appended at the end so the existing column order is untouched — tools read by header name and ignore unknown trailing columns, so older readers stay compatible.
gps_stab / gps_level: GPS-signal stability at the moment of the tap, independent of which street was chosen. gps_stab is a 0–1 score (weakest link of: jump — speed versus the median pace over the last ~15 s using median + K·MAD, so it self-calibrates and does not flag cycling; heading consistency; reported accuracy); gps_level is green / amber / red, or empty / none before enough fixes have arrived. Appended after the conf columns, same compatibility rule.

stand-still

Stand Still and Count

<sid>.zip · sid ends in _sta (v2.73)

Since v2.73 a stand-still export from traffic_counter.html has the same shape as the other apps: one ZIP named after the sessie_id (<yyyymmdd>_<hhmmss>_<xxx>_sta, fixed at Start), holding _sessie.csv and _telregels.csv for the pipeline, _onderbrekingen.csv only when the session was interrupted and continued, and the human-readable _overzicht.csv — the same text the app exported before v2.73. All four are written from the same state at the same moment.

Older exports. v2.18–v2.72 produced traffic_count_<timestamp>.zip with only the overview CSV; before v2.18 that CSV was a loose file. Telrapport reads all three forms (since v2.73 also the ZIPs directly): it finds the overview by its Traffic Count Export banner and takes the sessie_id from _sessie.csv when present, otherwise it synthesises one from the start time. The reconstructor refuses stand-still sessions: a fixed point has no route.

Filename markers & survey-type coding

A session's survey type is fixed three ways, in order of authority: the marker embedded in the filename, the app_type field in _sessie.csv, and — for reconstructed sessions whose modus is missing or wrong — the vocabulary of the tap types. The reconstructor (telreconstructie.html) applies exactly these rules.

Pocket modus letter. The modus letter (s/t/w/p) is part of the pocket sessie_id itself — not just the filename — so it survives reconstruction (…_pkt_w.zip → …_pkt_w_recon.zip).

Special cases. A single occurrence of a bike-parking type (fiets/brommer/breed/wrak) marks the whole session as bike parking. The reconstructor picks a schema from the profile, so the column set depends on the modus — there is no single reconstructed telregels layout. Read by column name, never by position: the auto variant even reorders, putting lat_gps / lon_gps before lat_marker / lon_marker where the raw file has them the other way round.
recon_status is the one column all three share: how the tap came out of the matcher.
The walk schema comes in two shapes: transect inserts a richting column after straat, the other walk modes do not. Both keep conf / gps_stab from the field session and both drop snelheid.
Both parking variants gain lat_marker / lon_marker and zijde. The raw coordinate is never overwritten: lat / lon (pocket) and lat_gps / lon_gps (auto, bike) still hold the position the phone reported.

GeoPackage export from telrapport

Since v3.1, telrapport.html can save the current map as a GeoPackage (suggested name telrapport_<yyyymmdd>_<hhmm>.gpkg; the user chooses). This is an output for viewing in QGIS, not an input: no tool in the suite reads it back, and the ZIPs (and the KNIME pipeline) are unchanged.

  • What you see is what you get. The layers are read from what telrapport has drawn: sessions, types and time windows that are switched off are left out, and clusters use the current cluster distance. The sessies table lists every loaded session, with op_kaart = 0 for the hidden ones.
  • Coordinates are EPSG:4326 (WGS84), as in the ZIPs. Points are at the position shown on the map (the marker position where there is one).
  • Styling travels with the data. Each map layer has a default style in the standard layer_styles table (useAsDefault = 1), so QGIS applies it on load: colours and categories from telrapport, clusters as pie charts sized like on the map (diameter 10 px + 5.6 px · √total) with the total as label. The QML is written in QGIS 3.34 form and also loads in QGIS 4.
  • A QGIS project is embedded (since v3.2) in the standard table qgis_projects(name, metadata, content), one row named telrapport; content is the .qgz (a ZIP holding telrapport.qgs) as hex text, as QGIS writes it. It sets EPSG:28992, layer order and display names, PDOK BRT-A grijs as basemap (WMTS in EPSG:28992; PDOK aerial and OpenStreetMap included but unchecked), the view on the counts, and a print layout A4 liggend (map at a round scale, title, legend, scale bar, north arrow, attribution). Open it with Project → Open From → GeoPackage.
  • The file name is part of the project. Layers are referenced as ./<file name>|layername=… (relative, so moving the file is fine; QGIS has no form for “this file itself”, so renaming breaks the project). Telrapport therefore asks for the name before writing: the browser’s Save-as dialog where available, otherwise a prompt followed by a download. Layer ids are <layer>_telrapport.
  • Not included: capacity polygons (not yet) and Static counts (by design). The export says so when capacity is on the map.
