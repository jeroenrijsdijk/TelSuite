TrafficCounterSuite — telrapport.html input specification
Telrapport.html accepts five ZIP archive types and one loose CSV. The format is detected from the app_type field in _sessie.csv for ZIPs, or from the file structure for loose CSV (stand-still). All CSV files use semicolon delimiters and UTF-8 encoding. Inside a ZIP, file names must start with the session ID and end with the suffix shown below.
auto

_netwerk.csvRequiredOSM way geometry as WKT

Move and Count Simple

*_pkt.zip
_sessie.csvRequiredSession metadata including type and icon
_telregels.csvOptionalPer tap: timestamp, type, lat/lon, osm_way_id, segment_index (v2.3+), street, snap confidence (v2.8)
_gps.csvOptionalGPS track with osm_way_id, segment_index (v2.3+) and street per point
_netwerk.csvOptionalOne row per ~40m segment with segment_index, segment_count and sub-LINESTRING (v2.3+)
_bezocht.csvOptionalPer visit to a segment: duration, GPS points, count of taps (v2.3: per (way, segment) instead of per way)
_sessie.csv
sessie_id;datum;start_tijd;eind_tijd;app_type;type;n_waarnemingen 20260514_131611_lok_pkt;2026-05-14;13:15:44;13:16:11;pocket;fiets;42
type: car / bike / ped / or free text when "Iets Anders" is chosen
_telregels.csv (v2.3+, conf columns v2.8)
sessie_id;nr;tijdstip;type;lat;lon;osm_way_id;segment_index;straat;conf;conf_level 20260514_131611_lok_pkt;1;2026-05-14T13:15:52;fiets;51.852540;4.332551;123456;2;Korenmarkt;0.87;green
segment_index (0-based) indicates which ~40m segment of the way was hit. For v2.2 ZIPs without this column, tools interpret it as 0.
v2.8 — conf / conf_level: snap confidence appended after the stable columns. conf is a 0–1 score (weakest link of: margin to the runner-up way, snap distance, GPS accuracy); conf_level is green / amber / red. They are appended at the end so the existing column order is untouched — tools read by header name and ignore unknown trailing columns, so older readers stay compatible.
v2.8 — trajectory-corrected: osm_way_id and segment_index are no longer the live (causal) snap. Just before export, reassignTrajectory() re-solves the whole path topology-first and each tap inherits the (way, segment) of its nearest-in-time GPS fix. Raw lat/lon are untouched. See snap_methodology.html §7.
_gps.csv (v2.3+)
sessie_id;tijdstip;lat;lon;nauwkeurigheid;osm_way_id;segment_index;straat 20260514_131611_lok_pkt;2026-05-14T13:15:50;51.852540;4.332551;5;123456;2;Korenmarkt
Route point at ≥5m displacement. segment_index comes from the same snap engine as the telregels — input for deriving _bezocht.csv per segment.
v2.8: per-point osm_way_id / segment_index are also trajectory-corrected (same reassignTrajectory() pass), so the track, the taps and the visits all reference the same corrected segments. Raw lat/lon and nauwkeurigheid are untouched.
_netwerk.csv (v2.3+)
osm_way_id;segment_index;segment_count;highway;geometrie_wkt 123456;0;3;residential;LINESTRING (4.3325 51.8525, 4.3329 51.8525) 123456;1;3;residential;LINESTRING (4.3329 51.8525, 4.3333 51.8525) 123456;2;3;residential;LINESTRING (4.3333 51.8525, 4.3337 51.8525)
One row per segment. Ways shorter than 60m stay whole (one segment); longer ways are split parametrically into pieces of ~40m. segment_count is repeated per row for self-contained interpretation.
_bezocht.csv (v2.3+)
sessie_id;datum;osm_way_id;segment_index;segment_count;straat;start_tijd;eind_tijd;duur_sec;n_gps;n_tellingen 20260514_131611_lok_pkt;2026-05-14;123456;2;3;Korenmarkt;13:15:50;13:16:05;15;14;3
One row per visit (a contiguous stay on one segment). Visits shorter than 5s or with fewer than 3 GPS points are filtered out. A gap of >30s breaks a visit. The date is in every row — self-contained for day-part classification in telplanning.
KNIME join: (sessie_id, osm_way_id, segment_index) as composite key.
Flux calculation: n_tellingen × 60 / duur_sec = passages/min — now per segment, more accurate for long streets.
For old v2.2 pocket ZIPs: python build_bezocht.py FILE_OR_DIR upgrades the ZIP in-place to v2.3 (idempotent — pass --force to redo).
v2.8: built from the trajectory-corrected taps and presence, so a visit's (osm_way_id, segment_index) always matches the taps attributed to it — no orphan segments, no empty week-profile cells. (build_bezocht.py is the older server-side path and is not trajectory-aware; ZIPs it produces keep the live snap.)
stand-still

Stand Still and Count

*.csv (loose file, no ZIP)

Unlike the other five formats, a stand-still export from traffic_counter.html is a single loose CSV — not a ZIP. The file is human-readable and uses a section-based structure rather than separate per-purpose CSVs. Telrapport detects it from the Traffic Count Export banner on line 2 and parses the three sections in order.

Structure — three sections separated by blank lines
sep=; Traffic Count Export Exported at;2026-05-22T17:03:11 Location / Notes;Voorstraat ter hoogte van nr 12 Start time;2026-05-22 16:32:18 End time;2026-05-22 16:47:18 Observed duration;15:00 GPS latitude;51.851400 GPS longitude;4.331200 GPS accuracy (m);8 GPS reliable;Yes (< 25m) GPS street;Voorstraat GPS city;Spijkenisse GPS country;NL GPS recorded at;2026-05-22 16:32:20 Extrapolation factor;4.0000;= 3600 / 900 seconds Vehicle Type;North counted;South counted;Total counted;... Car;42;38;80;... Bike;15;20;35;... TOTAL;57;58;115;... Timestamp Log Time;Vehicle;Direction 16:32:24;Car;North 16:32:31;Bike;South ...
Section 1 — metadata: key-value rows. Required keys for telrapport: Start time, End time, GPS latitude, GPS longitude. Optional but recognised: Location / Notes, GPS accuracy (m), GPS reliable, GPS street, GPS city, GPS country, Extrapolation factor.
Section 2 — summary table: starts at the Vehicle Type header. The first two count columns define the direction labels (dirA, dirB) for the entire session. Rows end at the TOTAL row.
Section 3 — timestamp log: starts after the Time;Vehicle;Direction header. Each row is one observation. Direction values must match the labels from section 2.
Vehicle type names are matched case-insensitively against the internal lookup table (SS_VEHICLE_LOOKUP); unrecognised types are dropped silently.
Session ID is synthesised by telrapport from the start time (e.g. ss_20260522_163218). Reloading the same file produces the same ID.
